# Bird's-eye lead: look at the whole project

Read `lead.md` and `brain.md` first. The Bird's-eye lead plans with
Mikey. It reads the plan files, the commits and the wiki, not the
code. It starts no worker. It runs every week, or after a play that
changes the plan.

## Steps

1. Read `vision.md`, `decisions.md`, `STATE.md`, `rows.md`,
   `inbox.md`, `play-notes.md` (the two newest sections) and the
   commits since the last Bird's-eye lead.
2. Say where the project is: what Mikey has played, what is built but
   not played, what is above its speed budget.
3. Check the direction. Does the next wave bring the game nearer to
   `vision.md` (a seed selects looks, sizes and timings, with
   weights)? Name the systems that have fixed constants.
4. Sort `inbox.md`: delete what is built, make rows from what is next,
   keep the rest.
5. Give Mikey the open taste questions ("Assumed" in
   `game/README.md`, "Proposed" in `decisions.md`), with options and a
   recommendation. Write decisions only after he agrees.
6. Check the way of working: the cycle, the gate, the usage limits.
   Propose a change if a step does not work.
7. Write `STATE.md` again: the phase, the cycle, one table for each
   lead, each row with a model and an effort.

## Rules

- Do not ask Mikey technical questions (R22).
- Do not plan more than one wave in detail. Later work is one line.

## End

Write `HANDOFF.md`. End your reply with **Weak spots**.

# Feel lead: from Mikey's play to new defaults

Read `lead.md` first. The Feel lead runs after Mikey plays. It does
the rows of the "Feel" table in `STATE.md`. Its aim: Mikey gets a
build with his notes applied on the same day.

## Steps

1. Read the newest zip in `~/Games/broken-friends-linux/playtests/`:
   `report.md` first, then the marks and their pictures.
2. Write Mikey's notes in `play-notes.md`, in his words, newest at the
   top. Delete the play rows that he did.
3. Ask Mikey only about feel and taste (R22). Give two or three
   options with a recommendation. Write a decision in `decisions.md`
   only after he agrees.
4. Do the tuning rows that his notes unblock. Most rows change
   `#[export]` defaults. Run two workers if the rows share no system.
5. If a note is a bug (a thing that is wrong, not a thing that feels
   wrong), add a row to the Fix table with the seed, the place and
   the mark. If a note needs new work, add a row to the Builder table.
6. Tell Mikey which build has the changes and what to look at.

## Rules

- Change the exported default and the Rust `Default` together, so the
  tests and the game agree.
- One note, one change. Do not tune a thing that Mikey did not name
  and the report does not show.
- If the report cannot answer a technical question, add a recorder
  probe and a row for the next playtest (R22).

## End

Write `HANDOFF.md`. The next lead is Bird's-eye if the play changed
the plan. If not, the next lead is Builder.
